# 데이터 소스 정책

## 기본 원칙

- 무료 소스와 무료 티어를 기본값으로 둔다.
- 유료 데이터 소스는 초기 범위에서 제외한다.
- 앞으로의 제품/기술 의사결정도 기본적으로 무료/저비용 우선으로 판단한다.
- LLM 비용도 무료/저비용 우선 원칙에 포함한다.
- 실제 수집 파이프라인보다 오프라인 하네스를 먼저 만든다.
- 하네스 샘플 데이터는 프로젝트가 직접 수집한다.
- public repo에는 API 키, 유료 데이터, 비공개 원문, 실제 고가치 후보 DB를 올리지 않는다.

## 수집 방식 우선순위

1. 공식 API 또는 공식 export
2. 무료 공개 데이터셋
3. 수동 CSV/JSON 업로드
4. 약관과 요청량을 검토한 제한적 크롤러
5. 유료 데이터 소스

초기 구현에서는 1-4만 검토합니다. 5는 사용자가 별도로 승인하기 전까지 제외합니다.

## 크롤러 검토 기준

크롤러는 무조건 금지하지 않지만, 다음 조건을 통과해야 합니다.

- 약관/robots/공개 접근성 검토
- 로그인, 우회, 캡차 회피, 세션 남용이 필요하지 않음
- 요청량 제한과 backoff 적용 가능
- 원문 저장 범위가 과도하지 않음
- 개인정보 또는 민감정보 수집 위험이 낮음
- 동일 데이터를 API/수동 업로드로 대체할 수 없는 이유가 있음
- 실패해도 전체 배치가 중단되지 않음

## 초기 무료 소스 후보

| 소스 | 용도 | 접근 방식 | 초기 판단 |
| --- | --- | --- | --- |
| Google Play | 앱 메타데이터, 경쟁앱, 리뷰 신호 | API/비공식 라이브러리/크롤러 검토 | 필수 후보 |
| Google Trends | 키워드 관심도 | 무료 도구/API 후보 검토 | 필수 후보 |

| 수동 CSV/JSON | 골든셋, 샘플 evidence | 직접 업로드 | Phase 1 필수 |

## 제외 또는 보류

- 유료 모바일 인텔리전스: Sensor Tower, data.ai, AppTweak, MobileAction
- 우회/로그인 자동화가 필요한 수집
- 성인, 도박 관련 데이터
- 개인정보나 민감정보가 중심인 원문 수집

## Phase 1 데이터 전략

하네스 선행 원칙에 따라 첫 구현은 실제 수집기가 아니라 수동 샘플 데이터로 시작합니다.

단, 샘플 데이터는 사용자가 직접 채우지 않고 프로젝트가 공개/무료 소스에서 직접 수집합니다.

필요 샘플:

- 앱 리뷰 샘플
- 앱 메타데이터 샘플
- 키워드/트렌드 샘플
- 커뮤니티 문제글 샘플
- 성공/실패 앱 골든셋

목표:

- evidence 스키마 검증
- opportunity 스키마 검증
- 근거 연결 검증
- 점수 계산 검증
- 보고서 생성 검증

## LLM 사용 정책

LLM 사용도 비용 정책의 일부로 봅니다.

- 무료/저비용 모델을 기본값으로 둔다.
- 모델 공급자는 교체 가능해야 한다.
- 로컬 모델 또는 저가 API 모델을 쓸 수 있도록 추출기 인터페이스를 분리한다.
- 고가 모델 사용은 명시적 품질 비교나 제한된 검증 작업으로 제한한다.
- 평가 하네스에는 품질 지표와 함께 비용 지표를 남긴다.

## 보고서 언어 정책

- 원문 evidence는 원어 그대로 저장할 수 있다.
- 최종 보고서는 한국어로 작성한다.
- 영어권 앱/리뷰/커뮤니티 데이터를 다뤄도 결론, 점수, 다음 액션은 한국어로 번역한다.
- 번역된 결론도 원문 evidence_id와 연결한다.
