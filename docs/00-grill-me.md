# Grill Me 질문지

이 문서는 프로젝트를 일부러 까다롭게 검증하기 위한 질문지입니다. 답변이 모호하면 구현 전에 스펙을 보강합니다.

## 1. 성공 정의

1. 이 시스템이 30일 동안 동작했을 때 "성공했다"고 판단할 최소 결과는 무엇인가?
2. 매일 보고서가 몇 개의 앱 기회 후보를 내야 하는가?
3. 후보의 품질은 출시 후 지표로 검증할 것인가, 아니면 조사 단계의 사전 기준으로 검증할 것인가?
4. 최종 목표는 직접 앱을 출시하는 것인가, 앱 아이디어 포트폴리오를 만드는 것인가, 또는 템플릿/리서치 상품화인가?
5. 한 후보를 "실행 가치 있음"으로 판정하는 최소 근거 기준은 무엇인가?

## 2. 타깃 시장

1. 한국 시장만 볼 것인가, 글로벌 시장을 포함할 것인가?
2. 앱 사용자는 어떤 집단을 우선할 것인가? 예: 직장인, 자영업자, 4050, 크리에이터, 개발자, 학부모.
3. 강의 메모에서는 광고 단가가 높은 사용자군을 추천했다. 우리는 이 가정을 어떤 데이터로 검증할 것인가?
4. 한국 버전으로 로컬라이즈할 해외 서비스/앱을 찾는 전략을 포함할 것인가?
5. 절대 건드리지 않을 카테고리는 무엇인가? 예: 의료, 금융투자, 도박, 미성년자 타깃, 민감 개인정보.

## 3. 수익화 전략

1. 초기 기본 수익모델은 광고인가, 구독인가, 유료앱인가, B2B 리드인가?
2. 광고 기반이라면 목표 국가, 예상 eCPM, DAU, 세션 수, 노출 수 가정을 어떻게 둘 것인가?
3. 구독 기반이라면 "광고 제거" 말고 매월 새로 줄 가치는 무엇인가?
4. 유료앱 후보를 허용할 것인가? 허용한다면 가격대와 구매 장벽을 어떻게 평가할 것인가?
5. 앱 자체보다 템플릿, 소스코드, 운영 자동화 패키지로 2차 수익화할 수 있는 후보를 점수에 반영할 것인가?

## 4. 조사 대상과 데이터 소스

1. 반드시 포함할 1차 소스는 무엇인가? 예: Google Play, Reddit, Google Trends, 외주의뢰 게시판, 앱 리뷰.
2. 유료 데이터 소스를 쓸 예산이 있는가? 예: Sensor Tower, data.ai, AppTweak, MobileAction.
3. 크롤링이 가능한 소스와 API로만 접근할 소스를 어떻게 구분할 것인가?
4. 약관상 자동 수집이 애매한 소스는 제외할 것인가, 수동/반자동 수집으로 둘 것인가?
5. "유효한 시장조사 대상"의 정의는 무엇인가? 최소 리뷰 수, 최근 업데이트, 국가, 카테고리, 키워드 검색량 같은 기준이 필요하다.

## 5. 방법론 엄격도

1. TAM/SAM/SOM 추정을 매 후보마다 할 것인가, 상위 후보에만 할 것인가?
2. JTBD(Job To Be Done) 분석을 필수로 할 것인가?
3. 경쟁앱의 1-3성 리뷰를 어떻게 샘플링할 것인가?
4. 검색량, 리뷰 불만, 외주의뢰, 커뮤니티 고통 신호 중 어느 것을 가장 강한 수요 증거로 볼 것인가?
5. 조사 결과가 틀렸음을 보여주는 반증 신호는 무엇인가?

## 6. 점수화

1. 후보 점수는 하나의 총점으로 볼 것인가, 다차원 점수표로 볼 것인가?
2. 가장 중요한 상위 3개 축은 무엇인가? 예: 수요 강도, MVP 난이도, 수익화 명확성.
3. "2주 안에 MVP 출시 가능" 기준을 어떻게 정량화할 것인가?
4. "실패해도 모듈이 남는가"를 어떤 항목으로 측정할 것인가?
5. 사람이 최종 판단해야 하는 영역은 무엇인가?

## 7. 보고서

1. 매일 보고서는 누가 읽는가? 창업자 본인, 개발자, 투자/지원사업 문서 작성자, 외부 고객.
2. 보고서는 한국어만 필요한가, 영어도 필요한가?
3. 보고서에는 몇 개 후보를 깊게 다룰 것인가?
4. 각 후보마다 PRD 초안까지 생성할 것인가?
5. 보고서가 바로 다음 작업 단위로 이어져야 한다면, 어떤 형식의 액션 아이템이 필요한가?

## 8. 하네스와 개선

1. 좋은 조사 결과의 정답지를 어떻게 만들 것인가?
2. 과거 성공/실패 앱 사례를 골든셋으로 만들 수 있는가?
3. LLM 추출 결과는 사람이 샘플 검수할 것인가?
4. 점수화 모델의 예측력이 실제 출시 성과와 연결되는지 몇 주 단위로 백테스트할 것인가?
5. 매일 파이프라인 변경이 보고서 품질을 악화시키지 않았다는 기준은 무엇인가?

## 9. 운영 제약

1. 월 운영비 상한은 얼마인가?
2. 매일 배치 실행 시간은 언제인가?
3. 실패 시 재시도, 부분 보고서, 알림은 필요한가?
4. 데이터 보관 기간은 얼마인가?
5. 개인정보, 약관, 저작권, 스토어 정책 리스크를 누가 최종 검토하는가?

## 10. 첫 번째 실험

1. 첫 2주 동안 조사할 앱 카테고리 3개는 무엇인가?
2. 첫 보고서의 품질을 어떻게 평가할 것인가?
3. 첫 MVP에서 반드시 빼야 할 기능은 무엇인가?
4. 첫 출시 후보를 실제로 만들 준비가 되어 있는가?
5. 이 시스템이 내릴 수 없는 결정은 무엇인가?
